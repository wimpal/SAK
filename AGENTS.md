# AGENTS.md — SAK (Swiss Army Knife)

Guidance for AI agents working in this repository.

## What this is

SAK is a personal, **local-first** desktop toolbox: one app, many small tools
(video utilities, file utilities, …). The #1 design goal: **adding a new tool
must be trivial** — one folder + one registry entry.

## Stack

- **Tauri 2** (Rust core, webview UI) — Windows target, `x86_64-pc-windows-msvc`
- **React 19 + TypeScript + Vite** frontend
- **Tailwind CSS v4** (via `@tailwindcss/vite`), dark theme
- **FFmpeg/FFprobe** bundled as Tauri sidecars (`src-tauri/binaries/`)
- **yt-dlp / Deno** bundled for music download (`node scripts/setup-music-tools.mjs`)
- Tauri plugins: dialog, fs, shell

## Commands

```bash
npm run tauri dev     # dev mode with hot reload
npm run tauri build   # production build — bundles the FFmpeg sidecars
node scripts/setup-music-tools.mjs  # yt-dlp + Deno sidecars (required for music downloader)
npx tsc --noEmit      # type-check
npx vite build        # frontend bundle check
```

Shell is Windows PowerShell 5.1: chain commands with `;` (`&&` is not supported).

## Layout

```
src/
  core/registry.ts   # tool metadata (id, name, icon, path, status) — single source of truth
  core/router.tsx    # hash router; one lazy-loaded chunk per tool
  core/Home.tsx      # home grid, generated from the registry
  ui/                # shared: ToolLayout, FilePickerButton, DropZone, ProgressBar, FfmpegStatus
  tools/<id>/        # one folder per tool; index.tsx default-exports the page body
src-tauri/
  src/lib.rs         # Tauri commands (e.g. ffmpeg_version)
  binaries/          # ffmpeg/ffprobe sidecars, triple-suffixed — never hand-edit
  capabilities/      # permission grants — update when adding plugin/sidecar usage
  icons/             # generated by `npx tauri icon` — do not hand-edit
assets/
  icon.svg           # brand icon SOURCE — edit this, then regenerate (see below)
scripts/
  generate-icon.mjs  # renders assets/icon.svg → assets/icon.png (uses sharp)
  setup-music-tools.mjs  # downloads yt-dlp + Deno into src-tauri/binaries/
  setup-calibre.mjs  # downloads Calibre into src-tauri/resources/calibre/
plan.md              # vision, features, roadmap — keep in sync as phases land
```

## Adding a tool (the core workflow)

1. Create `src/tools/<id>/index.tsx` with a default-exported component (page body
   only — `ToolLayout` provides header and back-nav).
2. Add an entry to `tools` in `src/core/registry.ts`.
3. In `src/core/router.tsx`, add a lazy import and one `toolRoute("<id>", …)` line.
4. If the tool needs native work, add a `#[tauri::command]` in
   `src-tauri/src/lib.rs`, register it in `generate_handler!`, and grant any new
   permission in `src-tauri/capabilities/default.json`.
5. Flip `status: "planned"` to `"available"` in the registry entry.

## Conventions

- **Styling**: dark zinc palette is the base; brand red (`bg-brand`, `text-brand`,
  `border-brand` — Victorinox #DA291C, defined via `@theme` in `styles.css`) is
  reserved for small accents: hover states, active states, progress, tool icons.
  No large red surfaces.
- **TypeScript strict**: `noUnusedLocals` / `noUnusedParameters` are on — no dead
  variables.
- **Lazy loading**: every tool stays a separate lazy chunk; never import a tool
  eagerly from `core/`.
- **FFmpeg**: always run through the shell-plugin sidecar from Rust (see
  `ffmpeg_version` in `lib.rs`). New sidecars require a triple-suffixed binary in
  `src-tauri/binaries/`, an `externalBin` entry in `tauri.conf.json`, and a scoped
  `shell:allow-execute` permission in `capabilities/default.json`.
- **Brand icon**: edit `assets/icon.svg` only, then run
  `node scripts/generate-icon.mjs` followed by `npx tauri icon assets/icon.png`.
  Everything in `src-tauri/icons/` is generated output.
- **File safety**: never overwrite a user's original file by default. Default
  output = suffix or a sibling/custom output folder; collisions must warn.
- **plan.md** is the living roadmap — mark phases done there as they land.
